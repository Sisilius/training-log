# Training Log

Мобильный дневник тренировок: GitHub Pages + Supabase (Postgres, Auth, RLS).

## Что уже есть

- Вход по email + паролю; magic link оставлен как резервный вариант.
- Данные хранятся в Supabase, доступны с телефона и компьютера.
- Каждый пользователь видит только свои записи (Row Level Security).
- Экспорт текущего дня в CSV и полный JSON-бэкап/импорт. JSON выгружается без `id`, `user_id` и `updated_at` — его можно присылать на анализ.
- Автозаполнение прошлой тренировки: только пустые поля и только выбранный день (Пн/Ср/Пт), без затирания введённого.
- Слоты упражнений: в каждом слоте 2–3 варианта, выбор и подсказка с ротацией.
- Отдельные числовые поля «вес» и «повторы», а для планки/кардио/переноски — свои поля.
- Бицепс в понедельник, трицепс в среду; в пятницу — оба.
- Экран тренировки показывает только нужный день: Пн/Ср/Пт выбираются по дате автоматически, в остальные дни — отдых с советами и следующей тренировкой.
- Заминка и растяжка после каждой тренировки.
- Плечевая профилактика на каждой тренировке: обратная «бабочка», наружная ротация, лопаточные подтягивания.
- Подсказка по RPE: 7 — ещё 3 повтора, 8 — ещё 2, 9 — ещё 1, 10 — максимум.
- Вес и повторы вводятся отдельными числовыми полями; старые записи `100×10`, `100x10` и `100*10` продолжают читаться.
- Таймер отдыха 60/90/120/180 секунд.
- Тёмная/светлая тема и крупный шрифт.
- Библиотека упражнений с техникой, ошибками и заменами.
- PWA: установка на телефон и офлайн-оболочка.
- Графики: рабочий вес, объём, боль в плече.
- Замеры тела: вес, живот, сон, настроение, сигареты. Запись можно открыть по дате или из истории и отредактировать.
- ГТО: тесты и график по выбранному показателю.
- Бег: дистанция, время, пульс, покрытие.
- Отсчёт до ГТО и гонки, недельная сводка и подсказки по прогрессии.
- Бесплатный тариф Supabase: 500 МБ базы, 50 000 MAU, 5 ГБ egress.

## Шаг 1. Supabase

1. Зарегистрируйся на https://supabase.com и создай новый проект.
2. Выбери регион поближе (например, Frankfurt).
3. Дождись, пока проект поднимется.
4. Открой **SQL Editor**, вставь содержимое `supabase/schema.sql` и нажми **Run**.
5. Затем вставь `supabase/schema_v2.sql` и тоже нажми **Run** — это таблицы замеров, ГТО и бега.
6. Затем вставь `supabase/schema_v3.sql` и нажми **Run** — это слоты упражнений (`slot_id`).
7. Открой **Authentication → URL Configuration**:
   - **Site URL**: `https://<username>.github.io/training-log/`
   - **Redirect URLs**: добавь
     - `https://<username>.github.io/training-log/`
     - `http://localhost:8000/` (для локальной проверки)
8. Открой **Project Settings → API** и скопируй:
   - **Project URL**
   - **anon public** key

## Если лимит писем исчерпан

Supabase на Free-тарифе ограничивает количество писем для magic link. Чтобы не зависеть от почты:

1. Войди в приложение (по ссылке или с уже открытой сессии).
2. Открой **«Ещё» → «Аккаунт»**.
3. Задай пароль (минимум 8 символов) и нажми **«Установить пароль»**.
4. Дальше входи по email и паролю — письма больше не нужны.

Для регистрации новых пользователей по паролю можно отключить подтверждение email: **Supabase → Authentication → Providers → Email → Confirm email** (для личного приложения это нормально). Для существующего аккаунта это не требуется: пароль ставится через `updateUser` после входа.

## Шаг 2. config.js

Открой `config.js` и вставь свои значения:

```js
window.SUPABASE_URL = "https://xxxx.supabase.co";
window.SUPABASE_ANON_KEY = "eyJ...";
```

`anon` key публичный, его можно держать в репозитории. **service_role key не вставляй никогда.**

## Шаг 3. GitHub Pages

1. Создай **публичный** репозиторий, например `training-log`.
2. Залей туда файлы из этой папки:
   ```bash
   git init
   git add .
   git commit -m "feat: training log with supabase"
   git branch -M main
   git remote add origin https://github.com/<username>/training-log.git
   git push -u origin main
   ```
3. В репозитории: **Settings → Pages → Build and deployment**.
4. Source: **Deploy from a branch**, Branch: **main**, folder: **/ (root)**.
5. Через минуту сайт будет доступен по адресу `https://<username>.github.io/training-log/`.

Если репозиторий приватный, GitHub Pages на бесплатном аккаунте не включится — нужен Pro или публичный репозиторий.

## Шаг 4. Проверка

1. Открой сайт.
2. Введи email и нажми «Отправить ссылку».
3. Перейди по ссылке из письма.
4. Введи подходы, например `40×12`, и обнови страницу — данные должны остаться.
5. Нажми «Экспорт CSV» — скачается файл за выбранную дату.

## Установка на телефон

**iPhone (Safari):** открой сайт в Safari → «Поделиться» → «На экран «Домой»». Пункта «Установить приложение» в Safari нет — это нормально.

**Android (Chrome):** открой сайт в Chrome → ⋮ → «Установить приложение» или «Добавить на главный экран». Если пункта нет: обнови страницу, подожди пару секунд и проверь, что открыт именно Chrome, а не встроенный браузер Telegram/Instagram.

В приложении раздел **«Ещё» → «Как установить»** показывает инструкцию под твою платформу.

### Если Chrome не предлагает установку

1. Открой **«Ещё» → «Диагностика установки» → «Проверить»**.
2. В строке должно быть: `SW: activated`, `SW controller: да`, `Install prompt: получен`.
3. Если SW не активен — нажми **«Сбросить кэш»**, дождись перезагрузки и проверь снова.
4. Проверь разрешение Chrome: `chrome://settings/content/installApps` (или Настройки → Настройки сайтов → Установка приложений).
5. Убедись, что открыт полный Chrome, а не встроенный браузер Telegram/Instagram, и что сайт не в инкогнито.

## Локальная проверка

В папке проекта:

```bash
python -m http.server 8000
```

Открой `http://localhost:8000/`. Не открывай через `file://` — Supabase Auth и редиректы могут не работать.

## Важные ограничения

- Free-проект Supabase **пауза после 1 недели неактивности**. Данные сохраняются, проект можно разбудить в дашборде.
- Автоматических бэкапов на Free нет. Раз в месяц делай **Экспорт JSON** (кнопка в разделе «Ещё») или `pg_dump`.
- Встроенная отправка писем у Supabase имеет лимиты. Если письмо не приходит — проверь спам и повтори позже. Для стабильности можно подключить свой SMTP.
- Если сайт станет публичным и популярным, смотри Pro-план ($25/мес): без пауз, ежедневные бэкапы, больше лимитов.

## Если «Ошибка сохранения: TypeError: Failed to fetch»

Это сетевой сбой, а не ошибка SQL. Проверь по порядку:

1. Открыт ли сайт по адресу `https://sisilius.github.io/training-log/`, а не локальный файл `file:///...`. С `file://` Supabase-запросы блокируются CORS.
2. Открой в том же браузере `https://qgndwqxesecfzcoiocus.supabase.co/auth/v1/health` — должен вернуться JSON с `GoTrue`. Если не открывается — домен блокирует сеть/VPN/AdBlock/Private DNS.
3. Выключи VPN, AdBlock, Private Relay и попробуй мобильный интернет вместо Wi-Fi.
4. Нажми в приложении «Проверить связь» — оно покажет, доходит ли до Supabase.
5. На ПК: F12 → Network, повтори сохранение и посмотри красный запрос (статус, CORS, DNS).

Данные при сбое сохраняются локально в браузере. После восстановления связи нажми «Проверить связь» — приложение попробует отправить их снова.
